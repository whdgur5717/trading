# 시장 데이터 제공자 경계

KIS, 금융위원회, OpenDART는 숫자와 날짜를 서로 다른 문자열 형식으로 반환하고,
성공과 실패를 표현하는 방법도 다르다. 이 형식을 내부 계약에 그대로 노출하면
서비스가 제공자별 필드와 오류 코드를 알아야 한다. 반대로 외부 응답을 변환하는
과정에서 요청에만 있던 값을 채워 넣으면, 어떤 값이 제공자의 응답이고 어떤 값이
애플리케이션의 판단인지 구분할 수 없게 된다.

생성된 OpenAPI 스키마는 외부 제공자가 보낸 응답을 검증하는 데 사용한다. 각
provider mapper는 검증된 응답의 숫자, 날짜, 빈 문자열과 nullable 표현을 내부
port가 요구하는 값으로 변환한다. 인증, 요청 전송, HTTP 상태와 제공자 업무 오류의
해석은 provider adaptor가 맡는다. mapper와 adaptor 밖의 서비스는 제공자 필드명과
오류 코드를 사용하지 않는다.

여러 제공자 중 하나를 선택하거나 제공자 응답에 없는 요청 문맥을 결과에 결합하는
책임은 `MarketDataPort` 구현에 둔다. 예를 들어 KIS 휴장일 응답에는
`quotationMarket`이 없으므로 KIS mapper가 이를 만들어내지 않는다.
`MarketDataAdaptor`가 요청에 포함된 시장과 변환된 휴장일을 결합해 port 결과를
완성한다.

이 경계 때문에 새 제공자를 연결할 때는 생성 스키마를 내부 모델처럼 사용하지 않고
해당 제공자의 mapper를 작성해야 한다. 제공자 고유의 정규화 규칙은 mapper에 남지만,
내부 시장 선택이나 다른 제공자와의 조합 정책은 mapper로 내려보내지 않는다. 수익
계산과 실시간 전달 흐름은 계속 `MarketDataPort` 계약에만 의존한다.
